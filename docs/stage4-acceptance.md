# 阶段 4 验收：报告快照与趋势

本阶段的“报告”是一次指标录入的固定快照，不是疾病诊断、患病概率或治疗建议。临床规则仍为待审核草案，仅在本地 `dev` 环境中预览；正式环境只保存指标，不返回阈值解读。

## 自己动手验收

1. 按 [本地开发说明](development.md) 启动项目，打开 [http://localhost:3000](http://localhost:3000) 并登录普通用户。建议新注册一个测试账号，避免旧记录影响观察。
2. 在“录入体测指标”中选择“血糖”和“空腹实验室血浆”，录入 `100 mg/dL`，测量时间选昨天。再以同样条件录入 `110 mg/dL`，测量时间选今天。两次记录应出现在“最近录入”。
3. 在第一条记录下点击“生成／查看这次的报告”。“我的报告与授权”应出现一份报告，包含原始数值、标准单位数值、测量条件、规则版本及来源。对同一条记录再点一次，报告编号和生成时间应保持不变，不应新增第二份。
4. 在“同类指标趋势”选择“血糖 · 空腹实验室血浆”。应看到两点折线和逐条数值。再录入一次“指尖血糖”，切换到“血糖 · 指尖”，它应独立显示，不能混入前面的空腹曲线。
5. 可沿用阶段 2 的医生授权流程：授权医生后，医生端只能看到被授权的报告快照；撤销后报告消失。医生端不能查看原始指标列表，也不能代用户生成报告。

趋势只显示最近 50 个同指标、同测量条件的数据点，纵轴不画医学阈值线。不同测量条件不能直接混用。当前页面的“最近录入”读取最近 100 条指标明细；它是操作列表，不代表完整历史导出。

## 自动化验收

后端以 `dev` 配置运行时，在项目根目录的 PowerShell 7 中执行：

```powershell
.\scripts\verify_stage4.ps1
```

脚本创建随机测试账号和少量测试指标，不删除记录。它验证报告快照、重复生成、八次并发请求、用户与医生角色隔离、趋势时间顺序和测量条件隔离。后端单元测试：在 `server/` 执行 `mvn test`；前端构建：在 `web/` 执行 `npm run build`。

## 接口

- `POST /api/reports`：普通用户提交 `{"entryId":"阶段 3 返回的 UUID"}`。同一用户、同一 `entryId` 只能有一份报告；重复调用返回原报告，规则更新后也不会悄悄重算历史快照。数据表上的 `(user_id, idempotency_key)` 唯一约束负责并发兜底。
- `GET /api/reports`、`GET /api/reports/{id}`：沿用阶段 2 的所有者／获授权医生访问控制。
- `GET /api/indicators/trends?code=blood_glucose&context=FASTING_PLASMA`：仅普通用户可查询自己的最近 50 个同类数据点，按测量时间升序返回；不合适的编码与测量条件组合返回 400。

请求需沿用阶段 2 的登录会话及 CSRF 令牌。报告 JSON 包含 `schemaVersion`、`sourceEntryId`、`values`、`rulesStatus`、`ruleVersion`、`interpretations` 等快照字段；旧虚构演示报告没有这些字段。
