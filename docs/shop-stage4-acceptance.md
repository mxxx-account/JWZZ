# 商家电商主线第四阶段：订单与模拟支付验收

## 完成范围与边界

用户把同一家演示店铺的商品加入购物车后，可提交演示订单。服务端在一个 MySQL 事务内重新核对店铺营业、商品上架、当前价格和可售库存；以库存行锁预留商品，并保存订单、商品名称与单价快照，再清空购物车。订单使用 `(用户 ID, 幂等键)` 唯一约束和用户行锁：网络重试或重复点击使用同一键会返回同一订单，不重复扣库存。

状态为 `PENDING_PAYMENT → PAID → ACCEPTED`，或 `PENDING_PAYMENT → CANCELLED / EXPIRED`。待支付订单 15 分钟后超时；后台每 30 秒扫描并释放。用户主动取消待支付订单也会释放。状态与库存变更处于同一事务，重复取消／重复超时不会再次回补。用户模拟支付后，商家可在首页的演示订单板块接单，预留库存转为已售；已支付订单不支持直接取消或退款。支付和接单都支持同状态重复请求，不会重复扣减。

“支付”只是数据库状态变化，**没有真实资金、处方审核、药品销售、发货、配送或退款**。订单限一家店铺；没有收货地址，不能用于真实交易。购物车不会锁库存，下单时才预留。商家手动设置的“目标库存”指可售库存，不包含已预留数量。

## 手工验收

后端需运行包含 Flyway V10 的当前版本；前端访问 `http://localhost:3000`。可沿用第三阶段的商家和用户演示账号。

1. 商家把至少一件演示商品上架、设置可售库存为 2，并开启演示营业。
2. 用户进入“药店”，加入 1 件到购物车，点击“提交演示订单”。应进入“我的订单”，显示订单号、商品与价格快照、`待模拟支付`、支付截止时间；购物车清空。商家库存应变为“可售 1、预留 1”。
3. 用户点击“取消订单”。状态变为“已取消”；商家库存应恢复为“可售 2、预留 0”。刷新页面后仍能看到该订单。
4. 再加入同一商品并下单，点击“模拟支付”。状态变为“已模拟支付，待商家接单”，页面明确不发生真实扣款。此时用户不能直接取消。
5. 商家登录首页，刷新演示订单，找到“待接单”订单并点击“接受演示订单”。订单变为“已接单”，库存应为“可售 1、预留 0”，可在库存流水看到预留与接单记录。
6. 超时验证可将待支付订单留置至少 15 分钟，再等后台最多约 30 秒；刷新订单，应看到“超时关闭”和库存回补。自动化测试使用缩短到期时间的方法验证同一逻辑，不必手工等待。

## 接口与权限

- 用户 `POST /api/shop/orders`：请求 `{ "idempotencyKey": "客户端生成的 UUID" }`，从当前购物车创建订单；重复键返回原订单。库存不足、商品下架或店铺暂停返回 409。
- 用户 `GET /api/shop/orders`、`GET /api/shop/orders/{id}`：仅自己的订单；其他人的订单返回 404。
- 用户 `POST /api/shop/orders/{id}/pay`、`POST /api/shop/orders/{id}/cancel`：模拟支付或取消，按当前状态控制。
- 商家 `GET /api/merchant/orders`、`GET /api/merchant/orders/{id}`：仅本店订单与明细；`POST /api/merchant/orders/{id}/accept` 仅接本店已模拟支付订单。
- 医生无权访问商城订单；用户无权访问商家订单接口。
