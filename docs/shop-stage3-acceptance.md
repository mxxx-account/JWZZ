# 商家电商主线第三阶段：搜索与购物车验收

## 完成的业务链路

商家将至少一项**有库存**的演示商品上架后，可以把草稿店铺切换为“演示营业中”；只有此状态下的已上架、有可售库存的商品才进入用户药店页。店铺暂停、商品下架、库存归零后，商品不再出现在新的搜索结果中。此处的“营业”仅是项目演示状态，不代表平台核验真实药店资质。

用户在“药店”页可按商品或店铺名称搜索，按品类筛选，使用默认排序或价格排序，查看商品详情、演示价格、店铺城市和地址，加入购物车并增减数量或移除商品。购物车保存在 MySQL，刷新或重新登录后仍在；目前**只能放同一家店铺的商品**，切换店铺须先移除原商品。当前没有定位、距离排序、真实附近药店、订单或支付。

购物车展示的是当前商品和价格信息，**不锁定库存，也不保证价格**。加入和调数量时会核对当时可售库存；商家后续下架、暂停营业或调整库存时，购物车条目仍保留并标记为不可购买，方便用户自行移除。第四阶段下单时必须重新校验价格、状态和库存，在事务内预留库存。

## 手工验收步骤

当前项目后端已由 Codex 在标准 `8080` 端口重启并运行，Flyway V9 已应用；前端仍为 `http://localhost:3000`。如果服务后来停止，按开发文档分别启动后端和前端。

1. 用商家账号登录。店铺若是草稿，选择一项演示商品，将可售库存设为至少 2，点击“上架”，然后点击“开始演示营业”。应看到“演示营业中”。若没有有货的上架商品，开始营业应被拒绝。
2. 退出，以新用户账号登录，在顶部进入“药店”。搜索商品名或商家店铺名，确认只出现有货商品及所属演示店铺。试用类别筛选、价格排序和“查看详情”。页面不应显示定位按钮或真实附近药店。
3. 将商品加入购物车，点击“购物车”，修改数量并刷新页面，确认仍在。尝试超过库存的数量，应提示库存变化／不足；尝试再加入另一家店铺商品，应提示先清理原店铺购物车。
4. 返回商家账号，把该商品下架或将店铺改回草稿。用户重新搜索时商品应消失，但原购物车条目仍可看到，并提示不可购买，可将其移除。
5. 页面底部和购物车应明确显示“没有真实下单或支付”。“下单功能待开发”按钮不可点击。

## 接口和权限

- 商家 `PUT /api/merchant/store/status` 只接受 `OPEN` / `DRAFT`；无有货上架商品时不能进入 `OPEN`。
- 用户 `GET /api/shop/products` 支持 `query`、`category`、`sort`、`page`、`size`；服务端仅查询演示营业中、上架且可售库存大于 0 的 SKU，分页大小最多 30。
- 用户 `GET /api/shop/products/{skuId}` 获取当前可展示的商品详情；状态变化后返回 404。
- 用户 `GET /api/shop/cart`、`POST /api/shop/cart/items`、`PUT /api/shop/cart/items/{itemId}`、`DELETE /api/shop/cart/items/{itemId}` 管理自己的一家店铺购物车。数量限 1～99，加入不同店铺或数量超过当前库存时返回 409。购物车写操作在事务内以用户行锁串行化，防止并发加入两家店铺破坏约束；这**不是**下单防超卖机制。
- 商家／医生不能调用用户商城接口；用户不能调用商家管理接口。购物车查询按当前用户 ID 隔离。
- 原定位与 OpenStreetMap 找店实现保存在 `web/src/app/patient/pharmacy/legacy-location-page.tsx`，当前路由不使用，也不会请求定位接口。
