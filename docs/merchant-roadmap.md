# 商家电商主线：五阶段实施与阶段一验收

## 当前边界

本主线是教学演示商城，不是真实药店或药品交易平台。商品、库存、订单、支付和商家聊天将按阶段实现；当前已完成**阶段一与阶段二，阶段二待用户验收**。商家自行注册与草稿店铺不表示经营资质已经核验。当前用户药店页仍只显示健康用品示例目录，不展示定位或附近药店，也不会展示商家后台的商品。

## 五阶段路线

1. **商家与店铺（已实现）**：`MERCHANT` 注册登录、商家首页、每账号一家草稿店铺、资料编辑、后端角色隔离。
2. **商品与库存（已实现，待用户验收）**：演示商品模板、店铺 SKU、上架下架、定价、库存调整和库存流水。默认商品不等于真实备货，初始可售库存为 0。
3. **搜索与购物车（未开始）**：仅展示营业中、已上架且可售库存大于 0 的店铺商品；商品详情、筛选、购物车。当前不启用定位排序。
4. **订单与模拟支付（未开始）**：单店订单、事务预留库存、幂等键、订单状态机、取消／超时释放库存，并发防超卖测试。仅演示支付，无真实资金。
5. **商家消息与质量验证（未开始）**：独立于医生咨询的用户—商家会话、订单关联、权限隔离、回归测试、压测与技术文档。

每个阶段完成后先由用户验收，再进入下一阶段，并单独提交 Git。

## 阶段一实现

- 后端新增 Flyway V7 `merchant_store` 表，`merchant_id` 唯一约束保证每个商家目前最多一家店铺。初始状态固定为 `DRAFT`；没有商品和营业能力。
- 本地 `dev` 配置允许商家自行注册；其他运行配置默认关闭商家自行注册。注册仍要求邮箱、姓名、至少 12 位密码。
- `GET /api/merchant/store` 读取自己的店铺；未建店返回 404。`POST /api/merchant/store` 创建，重复创建返回 409。`PUT /api/merchant/store` 修改，仅影响自己的店铺。用户、医生访问商家接口返回 403。
- 商家不能访问用户／医生消息、医生待咨询或报告详情接口；用户／医生原流程保留。
- 前端商家首页 `/merchant` 提供建店和修改资料表单。店铺未上架，用户药店页目前不会搜索到它。

## 如何启动并验收

如果前后端正在运行，请**重启后端**，让 Flyway 应用 V7 迁移，并让新角色配置生效；前端开发服务通常会热更新，但若看到旧页面也重启前端。保持本机 MySQL 可用。

终端一（项目 `server` 目录）：

```powershell
. .\.env.local.ps1
mvn spring-boot:run
```

终端二（项目 `web` 目录）：

```powershell
npm run dev
```

访问 `http://localhost:3000`。建议用两个**新的演示邮箱**分别注册商家甲、商家乙，不要使用真实经营者资料：

1. 在登录页选“注册 → 身份：商家”，填写邮箱、姓名、至少 12 位密码。注册后应一次进入“商家首页”。
2. 商家甲创建店铺，填名称、城市、演示地址和简介。应看到“草稿店铺”和成功提示。修改名称并刷新网页，修改应保留。
3. 再次点击品牌“见微知著”，应回商家首页而不是退出。直接访问 `/patient` 或 `/doctor` 应回到商家首页。
4. 退出并注册商家乙。商家乙应看到“尚未创建”，看不到甲的店铺；可自行建另一家店。
5. 以普通用户登录药店页，仍只看到示例用品目录，不出现新建的草稿店铺，也没有定位和附近药店。
