## 原因与修复

咨询、商家两种消息原先只提交 body。服务端已写入但回执丢失时，保留的草稿再次发送会重复插入。行锁不能识别逻辑重试。

现在每次逻辑发送携带 `clientMessageId`：

- Flyway V12 为两张消息表增加可空字段及“会话＋发送者＋客户端 ID”唯一索引。旧消息无需回填；旧接口调用不传 ID 仍兼容，但不承诺其重试去重。
- 发送事务先锁定会话、校验身份与当前权限，再以当前读检查既有 ID。相同 ID 和内容返回原消息；相同 ID 不同内容返回 409；只有新发送计入发送限流并执行写入／医生最新回复更新。
- 医疗与订单域保持独立。幂等命中不能绕过授权；撤权后旧 ID 也被拒绝。
- 前端按用户、消息域、会话在 sessionStorage 保存待确认消息文本及 ID；响应丢失、刷新后重试沿用该 ID。成功确认后清除。编辑为不同文本会生成新 ID。正常再发相同文字也生成新 ID，不按文本做全局去重。
- sessionStorage 属于当前浏览器会话的本地数据，不上传日志；仍含敏感草稿文本，应使用可信设备。它不是跨设备发件箱，清除浏览器会话存储后不承诺恢复原重试 ID。
