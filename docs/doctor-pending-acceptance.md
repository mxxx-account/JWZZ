# 医生待咨询首页验收记录

日期：2026-11-06。医生首页显示“待咨询的报告”和“刷新待咨询列表”，不再把所有已授权报告都当作待处理咨询。

## 状态流程

1. 用户只授权报告：医生已有报告读取权限，但**没有咨询请求**，首页不显示待咨询卡片。
2. 用户选择该医生并提交问题（可留空使用默认问候）：后端在一个事务中保存咨询请求及首条消息；医生首页约 8 秒内或窗口获焦时出现该报告、用户编号和用户附带的消息。此时医生消息列表不显示该会话，直接访问其会话 ID 返回 404。
3. 医生点击“接受咨询并进入消息”：后端使用带 `status='OPEN'` 条件的更新，避免重复接受；成功后跳转消息页，左侧出现该会话，医生可查看首条消息并回复。待咨询卡片移除。用户端会话从提交时起就存在并保留消息，不会因等待医生而丢失。
4. 用户撤销报告授权：医生待咨询卡片或已接受的会话不再可见，后续访问和发送均被拒绝。

## 验证

- 浏览器端到端：医生首页已打开，用户授权但未提交咨询时没有待咨询卡片；提交后卡片出现；医生点击接受后进入指定会话，能看到用户消息并回复。另一条用例覆盖两次咨询、未接受时医生聊天列表不可见、接受后出现及未读状态。
- `./scripts/verify_messages.ps1`：验证未接受时医生消息列表无该会话，接受后出现未读会话，撤销授权后再次消失。
- `mvn -o test`：11 项通过，1 项未配置真实数据库时条件跳过；`npm run typecheck` 通过；`npm run test:e2e`：3 条用例通过。

“创建聊天窗”在此指**医生端开放并显示聊天界面**，不是接受时才写第一条消息到数据库。后者会让用户等待期间的消息无处保存，也与用户提交后可查看自己消息的既有行为冲突。
