# 药店探索页：功能、数据边界与验收

> 当前版本已进入商家商城第四阶段：本页展示有货的演示商家商品、单店购物车、演示订单与模拟支付。定位与附近药店继续隐藏。当前验收以 [第四阶段文档](shop-stage4-acceptance.md) 为准；以下是此前阶段的历史记录。

> 当前状态（2026-11-07）：根据产品调整，药店页默认**不展示定位入口、定位结果、附近药店及其搜索结果**。现阶段仅保留健康用品示例目录、分类和本地关键词搜索；这不是实时商品库存或可下单商城。此前下文关于定位和附近药店的说明是历史实现记录，当前页面不适用。定位、地图查询和药店列表代码未删除；如以后恢复，需显式设置 `NEXT_PUBLIC_ENABLE_LOCATION_DISCOVERY=true` 并重新评估页面文案、测试及地图服务可用性。

## 当前版本验收

1. 用户登录后进入“药店”：看到“健康用品目录”和六项示例用品，不出现定位按钮、城市选择、定位状态及附近药店列表，也不弹出浏览器定位权限框。
2. 切换用品分类，搜索“血压计”：仅出现匹配的示例用品和“暂无商家库存/下单”的边界说明，不显示附近药店。
3. 搜索不存在的用品：显示空状态；返回目录后仍能切换分类。窄屏页面不应横向溢出。

## 历史实现记录（当前默认隐藏）

## 当前实现

用户登录后从顶部“药店”进入 `/patient/pharmacy`。首页提供搜索栏、健康用品示例品类和附近药店；输入药品或商品名称后进入桌面搜索结果布局，药店按距离从近到远排列，可滚动浏览。点击“使用当前位置”才调用浏览器定位；拒绝授权时可选择武汉、上海、北京的市中心示例坐标体验页面。定位需要浏览器安全上下文（localhost 或 HTTPS）。

定位成功后独立显示绿色成功提示，并尝试通过后端逆地理编码显示“省 · 市 · 区”的大致地区。地区服务失败时仍明确显示“定位成功”，附约两位小数的坐标提示；附近药店查询失败另以橙色提示，两种状态不混淆。示例城市明确标为非真实定位。

Java 后端 `GET /api/pharmacies/nearby` 只允许用户角色调用，校验坐标、限制每用户每分钟 12 次，向 OpenStreetMap 的 Overpass API 查询 `amenity=pharmacy`，以 WGS84 坐标计算直线距离，筛出 5 km 内最多 30 家。坐标在请求第三方前四舍五入到约 100 m；查询结果只在服务进程内缓存 10 分钟，不写入 MySQL 或用户账号。公共 Overpass 实例可能限流、超时或缺少某地数据，不能作为生产级 POI 服务保证。

地区名称由 `GET /api/pharmacies/region` 查询 Nominatim；经纬度先缩减到约 1 km 精度，结果仅在单个服务进程内缓存 1 小时，默认外部地址可通过 `JWZZ_REVERSE_GEOCODE_URL` 切换。单实例执行至少 1 秒的上游请求间隔，并使用专用 User-Agent；公共服务仅适合低流量原型，多实例部署或正式产品需更换有服务保障的地理编码提供商。地区名称是近似行政区划，不能当作精确地址。

示例城市且地图服务失败时，页面显示三家**明确标注为“虚构演示”**的药店，不提供地图或电话链接。真实当前位置查询失败时只显示错误与重试，不混入虚构商家。

## 重要边界

- “电子血压计”等六个健康用品是**示例品类**，不是实际商品目录、销量榜、评分榜、库存或价格。
- 搜索结果是**附近可联系的药店**，不是已确认出售所搜商品的药店。库存、报价、营业状态和资质均需进一步核实。OpenStreetMap 位置不代表药品零售资质认证。
- 当前没有购物车、订单、付款、处方审核、药品配送或基于个人指标的药品／保健品推荐。上线真实交易前，需要与合规药品销售主体及实时商品/库存/订单系统对接，并完成相应资质、处方与药学服务流程。
- 位置来源为 [OpenStreetMap](https://www.openstreetmap.org/copyright)，药店标注可能不完整或过时；页面包含署名。地图和浏览器定位的技术说明分别见 [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API) 与 [MDN Geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)。网上药品销售的约束见[《药品网络销售监督管理办法》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_27f2fba302ab48239dfde1a5b5095156.html)。

## 手工验收

1. 启动原有 MySQL、后端与前端，用户登录后点击导航“药店”。医生账号不能访问药店接口。
2. 不点击定位时确认不弹权限框；点击“使用当前位置”后允许或拒绝，检查对应反馈。允许后应立即显示定位成功，地区解析成功时显示省市区；即使解析或药店查询失败，定位成功提示仍保留。也可选择示例城市。
3. 查看附近药店卡片的距离顺序；点击地图链接或有号码时的“致电药店”。地图服务故障时，示例城市会显示虚构演示卡片，真实定位不会。
4. 搜索“血压计”或任意药品名称，确认进入搜索结果页面、保留库存待核实提示；返回首页、切换健康用品分类。
5. 把浏览器宽度调至约 390px，检查搜索栏、导航、药店卡片没有水平溢出。

## 本轮验证

- `mvn -o test`（显式连接本机 MySQL）：18 项通过、0 失败、0 跳过；药店单元测试覆盖地图节点/道路中心解析、距离计算、5 km 过滤与排序，以及地区名称解析。
- `npm run test:e2e`：8 项通过；覆盖导航、示例城市、搜索结果、定位成功显示地区、地图与地区服务同时失败时仍显示定位成功、演示边界、窄屏布局及原有用户／医生流程。
- `npm run typecheck` 与 `npm run build`：通过，生产构建包含 `/patient/pharmacy`；构建后已恢复前端开发服务。
- 直接 HTTP 验证：附近药店接口未登录 `401`、用户注册 `201`、登录 `200`、非法坐标 `400`、当前网络的地图上游失败 `502`。地区接口未登录 `401`、非法坐标 `400`、本机逆地理编码上游失败 `502`；因此本机目前只能显示“定位成功＋约略坐标”，不能声称已经实测解析出真实行政区。
- 本机请求公开 Overpass 节点曾返回 406/504，因此**未声称在当前网络下实测取得真实附近药店**。页面会如实显示错误或带标注的示例结果；后续可配置 `JWZZ_OVERPASS_URL` 指向可用节点，或接入有服务保障的 POI 供应商。
