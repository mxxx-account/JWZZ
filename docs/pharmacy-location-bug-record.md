# 药店页定位成功状态不明确：原因与修复

日期：2026-11-07

## 现象

浏览器取得定位后，顶部只写“当前位置”，但没有成功提示或地区名。若随后药店地图接口失败，页面出现“地图服务暂时无法返回附近药店”，用户无法判断定位是否成功。截图所示正是“定位已取得坐标、地图找店失败”两件事被混淆。

## 根因

旧实现的 `getCurrentPosition` 成功回调只把经纬度保存到页面状态，`label` 固定为“当前位置”；没有逆地理编码，也没有独立的定位成功状态。紧接着自动调用 `/api/pharmacies/nearby`，其错误提示与定位展示靠得很近，形成“地图失败＝定位失败”的视觉误导。

## 修复

1. 定位成功即显示独立绿色状态，绝不等待药店查询；药店接口失败继续用独立橙色提示。
2. 新增用户专用 `/api/pharmacies/region`，以约 1 km 精度向逆地理编码服务查询大致省、市、区，并显示在位置栏。
3. 逆地理编码失败时保留“定位成功”，仅说明地区名称暂不可用，并展示约略经纬度；不猜测具体行政区。
4. 地区查询有每用户限流、单实例全局 1 次/秒约束与 1 小时内存缓存。坐标不写入账号或数据库。公共地理编码服务若长期不可用，需替换供应商。
5. 切换示例位置会取消旧定位请求的 UI 更新，明确说明示例位置不是当前定位。

## 回归验证

浏览器用例分别模拟地区解析成功、地区与药店服务均失败，确认两种情况下定位成功信息都能正确呈现；原有用户与医生流程一并运行。后端测试验证行政区名称拼接不重复，缺少地址时不伪造名称。
