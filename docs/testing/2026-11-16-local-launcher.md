## 范围与环境

- Windows、本机 PowerShell 7.6.9；脚本要求 7.4+，利用 `Start-Process -Environment` 隔离子进程环境。
- 本轮只增加启动辅助脚本、非敏感设置、忽略规则及文档；没有修改前端、Java 或 Python 网关业务逻辑。
- 使用硬编码的 `Synthetic...` 虚构测试数据，在项目 `.local-run/launcher verify <随机编号>/` 内测试。**未读取或配置用户的真实 API Key／默认凭据目录，未连接业务数据库，未调用 DeepSeek，未停止或重启现有应用服务。**
- 测试会启动自身的短生命周期 PowerShell 子进程，以及监听随机回环端口的假健康接口；完成后清理这些进程和本次临时目录。真实应用的 3000／8080／8091 端口不被占用。

## 调试中发现并修复的问题

1. **执行环境的 ACL 限制。** 自动化受限环境不能可靠保留目录 ACL，导致权限断言失败。改在普通 Windows 用户环境运行仅使用虚构数据的离线测试；保存函数也增加落盘后权限校验，无法限制目录权限时不保存凭据。没有通过放宽安全断言绕过问题。
2. **重复写 ACL 可能触发额外特权要求。** 首次保存通过后，重复给已受限目录写入安全描述符出现 `SeSecurityPrivilege` 错误。改为只调整访问控制列表，并在目录已满足当前用户独占权限时复用，避免不必要的二次 ACL 写入；更换 Key 场景复验通过。
3. **环境变量清除中的空值转换。** PowerShell 调用 .NET 时，普通 `$null` 可能被转换为空字符串，导致新增变量只是变为空值而没有删除。改用 `[NullString]::Value`，并对读取配置前后全部环境变量的名称、数量和值做断言；复验通过。

## 未验证／需用户验收

- 未代替用户在交互提示中输入真实 Key；没有验证真实供应商 Key、余额或当前模型可用性。
- 没有用新启动器运行真实前端、Java 和 Python 全套服务；没有执行真实应用的 Ctrl+C 停止／再次启动验收。上述环节按 [操作说明](../local-startup.md) 第 4–6 节由用户操作。
- 没有模拟换 Windows 账号、换电脑或重装系统。DPAPI 的账户／机器绑定是设计前提，本轮自动化覆盖的是当前用户加密／解密，而不是跨机器迁移。
- 没有做生产部署、进程崩溃后自动重启或强制关闭终端后的进程回收保证。运行脚本时保持终端打开，正常停止使用 Ctrl+C。
- 本轮不是业务功能、数据库迁移或完整前后端回归测试，不替代此前的测试报告。
