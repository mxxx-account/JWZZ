# 消息页迭代验收（阶段 6 暂缓）

这次迭代把阶段 5 的一次性咨询扩展为持续对话。页面和医生账号仅供本地演示，不代表真实医生在线坐诊或正式医疗服务。不要输入真实患者资料。

## 启动与账号

按[本地开发说明](development.md)启动 MySQL、后端和前端，打开 `http://localhost:3000`。Flyway 自动执行 V5 迁移，不要手工改表。

- 用户：可用原有测试用户登录，或在首页注册一个新的 `.invalid` 演示邮箱；注册只存账号，不发送邮件。
- 全科：`doctor@jwzz.local`
- 心血管内科：`doctor.cardiology@jwzz.local`
- 内分泌科：`doctor.endocrinology@jwzz.local`

三个医生演示账号共用 `server/.env.local.ps1` 中 `DEMO_DOCTOR_PASSWORD` 的本地值。密码不写入 Git 文档。医生在工作台或消息页保持打开时，目录会显示“在线”，90 秒没有活跃心跳后显示“离线”；这仅表示演示账号页面近期活跃，不代表可即时接诊。

## 完整流程

1. 用户登录，录入体检指标，从“最近录入”生成报告。到“我的报告与授权”，查看科室选择提示与全部/在线/三科筛选。提示只使用已录入的报告类别及参考标签，无法判断病情严重程度或胸痛、头晕等症状。
2. 选择一位医生，点击“授权…查看此报告”。当前授权名单应出现该医生。可以对另一份报告选择不同医生；授权逐份报告生效。
3. 在“向医生发起消息”中留空，点击“提交咨询并打开消息”。应跳到用户消息页，第一条为“您好，请帮我看看我的指标报告！”。也可输入自定义问题再提交。若一份报告授权了多位医生，先选中要咨询的已授权医生。
4. 医生用对应账号登录，在首页“待咨询的报告”中看到报告和用户附带的消息；仅授权、尚未提交咨询的报告不在此列表。点击“接受咨询并进入消息”后才跳转医生消息页，左侧生成该会话，输入回复并发送。未接受前医生消息列表不显示该会话，也不能通过会话 ID 打开；用户侧消息先保存，用户消息页仍可看到。
5. 用户继续发消息，医生继续回复，确认完整历史留在同一会话。左侧可搜索、筛选未读、切换会话；Enter 发送，Shift+Enter 换行。它是轮询的异步聊天，不是 WebSocket 实时通信。
6. 用户在报告页撤销该医生的授权。医生端的待咨询卡片或已接受会话应消失，不能继续读取或发送；用户仍可看自己的历史消息，但该会话不能继续发送。再次授权后可继续使用。
7. 换另一医生账号登录，不能看到定向发送给首位医生的会话。非本人用户也不能访问会话 ID。写接口需登录及 CSRF 令牌，消息写入有限流。

医生目录现在展示医生资料中的姓名和注册邮箱，可按科室按钮、在线状态下拉框（全部/在线/离线）筛选；也可在报告下输入已存在的医生账号邮箱直接授权。普通用户邮箱及不存在的邮箱不能被授予医生权限。三个内置姓名均为虚构演示资料。

当前版本在 `dev` 配置下开放**演示医生**自行注册，须填写姓名与科室，但没有身份和执业资质审核；非开发配置默认关闭。正式医生入驻必须加入管理员身份与执业资质审核，不能把当前演示账号当作真实医生。消息页未读标号的排查和修复记录见[独立问题记录](chat-unread-bug-record.md)。

## 注意边界

科室提示仅帮助选择：单项血糖偏离优先内分泌，血压偏离优先心血管，血脂可按同时关注的血糖或血压选择内分泌或心血管，多类异常可先由全科梳理。系统没有症状、病史、复查结果，也没有可靠的“轻度/明显”判别输入，因此不会自动推断急症或给出具体治疗方案。有胸痛、严重呼吸困难等急症应及时寻求线下急救，不要等待聊天回复。

## 新接口

`GET /api/doctors`（用户目录）；`POST /api/doctor/presence`（医生活跃心跳）；`GET /api/messages/conversations`、`GET /api/messages/conversations/{id}`、`POST /api/messages/conversations/{id}`、`POST /api/messages/conversations/{id}/read`。原阶段 5 的咨询接口保留兼容。
