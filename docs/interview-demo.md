# 见微知著面试演示：报告 → 咨询草稿 → 医生回复

建议 6–8 分钟。先讲「把一份体检记录变成可与医生沟通的问题」，再展示 AI 怎么参与。平台不提供诊断、处方或急症响应；医生、体检数据和商城支付都使用演示数据。旧 NHANES/DKD 研究原型未接入这条流程。

## 演示前准备

1. 打开 MySQL，按[本机启动说明](local-startup.md)使用一键启动命令。如果现场不依赖外部模型，用不带 `-WithAi` 的命令；如果要展示模型，事前验证已保存的凭据能完成调用。不要在投屏时录入或展示 API Key、内部令牌、数据库配置或原始日志。
2. 准备两个独立浏览器会话：普通窗口登录虚构患者，另一浏览器配置文件或无痕窗口登录虚构医生；记下医生注册邮箱，用于精确授权。同一普通窗口的两个标签页通常共享登录状态。
3. 在患者端录入两次演示用血压：同为居家测量、同为非妊娠成年人，示例较早一次 `122/78 mmHg`、较新一次 `128/78 mmHg`，用两个不同且不在未来的测量时间。为后一次生成报告，记下编号。保留一份尚未授权、尚未发过咨询的报告供演示；正式开始前回到「我的报告与授权」，选定它。
4. 准备[架构图](architecture.md)、[回归记录](testing/2026-11-16-demo-regression.md)。若要演示商城，另备一家有上架商品和可售库存的演示店铺；不在主流程临时建店。

## 主线时间表

| 时间 | 操作 | 可以这样讲 |
| --- | --- | --- |
| 0:00–0:40 | 打开患者首页，说明三个角色与各自边界 | 「今天重点是体检记录到医生沟通，商城是独立的模拟交易模块。」 |
| 0:40–1:35 | 打开较新的报告，展示原始记录、同条件历史与差值 | 「报告保存生成时的数据和规则版本；对比由 Java 查找合格的历史记录，不交给模型猜。」 |
| 1:35–2:20 | 保持模型勾选关闭，点击「生成咨询草稿」，看「本地模板 · 未调用 AI」 | 「不用访问外网也能生成草稿，本地模板是默认方式。」 |
| 2:20–3:25 | 点击「调整生成选项」，选择咨询重点；有网且提前验收过则勾选外部模型、重新生成。成功展示「Python 模型辅助」；否则留在模板 | 「只给模型测量场景、有无可比历史和选定的咨询重点。模型选主题，Java 负责渲染文字；不发送体检数值和患者身份。」 |
| 3:25–4:35 | 在「咨询草稿」补一句自己的问题，按邮箱授权这位医生，点击「填入咨询草稿」。先停一下，展示「尚未发送」，再点「提交咨询并打开消息」 | 「生成不会授权，填入也不会发送；能访问报告的是被授权的医生，咨询必须经用户明确提交。」 |
| 4:35–5:45 | 医生窗口首页确认「待咨询」有这条编辑后的问题，点击「接受咨询并进入消息」，输入演示回复。用户窗口等待轮询出现回复 | 「接受后才开放医生会话。当前是异步轮询，不是实时问诊。」 |
| 5:45–6:25 | 患者回报告详情撤权，医生窗口刷新，确认会话不再可访问 | 「撤权不只是页面隐藏；回归也断言直接读取和发消息会被后端拒绝。」 |
| 6:25–7:30 | 打开架构图与回归记录，总结一次技术取舍 | 「外部模型只做可验证的选择题；网络故障可以回退，核心咨询流程不依赖模型。」 |

## 现场出现故障时

- **模型超时、额度不足或校验失败**：展示页面的本地模板回退提示，照常编辑、授权并提交。若是主动不勾选，则应显示「未调用 AI」，不要把它说成已经演示了故障回退。
- **现场无外网**：用模板完成演示。可展示[回归记录](testing/2026-11-16-demo-regression.md)中本机假模型的成功与 429／异常输出分支，说明那是链路和契约测试，不是真实供应商可用性证明。
- **无法启动**：在启动终端查看本次 `Local logs`，按[启动说明](local-startup.md)核对端口、JAR 和 MySQL；面试现场时间紧时讲架构与已有验证记录，不把未跑通的环境写成已通过。

## 备选 3 分钟：库存与订单消息

从预置店铺搜索有库存商品 → 加购物车 → 下单预留库存 → 模拟支付 → 商家接单 → 从订单进入商家消息。需要展示取消时，用另一张待支付订单取消，确认库存回补，而不是取消已接单的那张。若面试官问并发，展示[订单事务与并发验收](shop-stage4-acceptance.md)和[最终回归](testing/2026-11-08-final-regression.md)：事务预留、防超卖、重复提交幂等、取消回补一次；商家会话与医生报告隔离见[订单消息验收](shop-stage5-acceptance.md)。支付和交易均为模拟，不涉及真实扣款或药品销售。
