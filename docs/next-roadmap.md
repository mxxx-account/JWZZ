## 阶段 1 决策

- 维持 HTTP 轮询，不先引入 WebSocket／消息队列／分布式锁。
- 会话列表按不可变会话 ID 倒序分页（每页 20），避免消息到达改变排序字段导致跨页遗漏；已加载列表刷新摘要，搜索和未读筛选明确限定已加载会话。后续如需全库搜索和按活跃度排序，单独设计。
- 消息首次获取最新 50 条，向上按 beforeId 取历史；轮询按 afterId 取新消息，消息 ID 去重、升序合并。每请求最多 100 条，超量增量分批补齐。
- read 必须携带实际展示的 lastReadMessageId；校验它属于该会话，GREATEST 防止迟到的请求回退游标。不能将数据库最新 ID 当成用户已经看到的 ID。
- 患者／医生和用户／商家两套授权边界不合并，只复用前端分页与滚动实现。
- 旧数组列表接口暂保留供其他入口兼容，新聊天界面改用 /page。已读接口契约变更，需要前后端同时更新；旧客户端缺少游标返回 400，不误清未读。
- 不修改现有迁移文件，消息表已具备 (会话 ID, 消息 ID) 索引。本阶段不宣称消除所有列表查询成本。
