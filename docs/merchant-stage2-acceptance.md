# 商家电商主线第二阶段：商品与库存验收

## 本阶段交付

商家创建店铺后，系统自动生成三项演示健康器械（电子血压计、血糖仪、电子体温计），其价格是可修改的演示占位价，**可售库存均为 0、默认未上架**，不表示真实备货。已有草稿店铺由 Flyway V8 迁移补齐同样的三项演示商品。

商家还可从六项示例商品模板中选择未加入的品类，或添加自定义演示用品；可以编辑名称、说明、演示售价，调整可售库存并写入备注、查看最近 100 条库存流水，以及上架、下架、移除和恢复商品。“移除”是保留历史数据的软删除，恢复后为未上架状态。库存变更使用数据库事务和行锁，流水记录变更前后数值。价格由后端以“分”保存，前端按“元”显示，不使用浮点数在数据库保存金额。

**当前范围限制：** 店铺仍为草稿，商品上架只作用于商家后台；用户药店页尚不显示商家商品，也不能搜索库存、下单或支付。这些属于后续第三、四阶段。没有真实药品或医疗器械经营资质审核，不得把演示目录用于真实销售。

## 手工验收步骤

1. 先停止旧的 8080 后端并重新启动，让 Flyway 应用 V8 迁移、加载新版商品接口。PowerShell 在 `server` 目录运行 `. .\.env.local.ps1`，再运行 `mvn spring-boot:run`。看到 “Successfully applied 1 migration ... version v8” 或 “Current version ... 8”，以及 “Started JwzzApplication” 后再打开页面。前端在 `web` 目录运行 `npm run dev`；若已运行，通常会热更新。
2. 在 `http://localhost:3000` 以商家登录。若已有草稿店铺，商品管理区应有三项预置演示商品，每项都显示“未上架”和“可售库存：0”。没有店铺则先创建一家。
3. 从模板选择“防护口罩”，填入 9.90 元并加入店铺；再创建一个自定义演示用品。刷新页面，确认仍在。
4. 对一个商品选择“编辑资料”，修改名称或价格；选择“调整库存”，把目标库存设为 5，填写“演示入库 5 件”。查看库存流水，应能看到 `0 → 5（+5）` 和备注。
5. 尝试上架、下架、移除、恢复。恢复后的商品应为未上架；历史流水仍在。
6. 退出并以另一商家登录。只能看到自己的店铺商品，不能看到或修改上一商家的商品。普通用户药店页仍是示例用品目录，不出现商家店铺或库存。

## 接口与约束

- `GET /api/merchant/templates`：演示商品模板。
- `GET /api/merchant/products`：当前商家店铺商品；未建店返回 404。
- `POST /api/merchant/products`：用 `templateId` 选品，或提供 `name/category/description` 自定义；均需 `priceCents`。同一模板不能重复加入同一店铺，重复时返回 409。
- `PUT /api/merchant/products/{skuId}`：修改本店未移除商品的名称、说明、价格。
- `PUT /api/merchant/products/{skuId}/status`：只接受 `ON_SHELF`、`OFF_SHELF`、`ARCHIVED`；移除后可恢复。
- `PUT /api/merchant/products/{skuId}/inventory`：将可售库存设置为 0～1000000 的整数，可附 `note`；负数返回 400。
- `GET /api/merchant/products/{skuId}/inventory/ledger`：最近 100 条库存流水。
- 用户、医生访问这些接口返回 403；商家访问其他店铺商品按不存在处理，返回 404。所有写操作保留会话认证与 CSRF 校验。
