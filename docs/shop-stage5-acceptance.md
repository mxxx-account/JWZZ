# 商家电商主线第五阶段：订单消息与质量验收

## 功能与边界

用户在“药店 → 我的订单 → 联系商家”发起订单会话；若未输入首条消息，系统发送默认的订单问候。每张订单最多一条会话，重复点击返回原会话，不重复发送首条消息。用户通过导航“商家消息”查看与回复；商家通过导航“消息”查看本店用户的订单会话。两侧显示订单编号、最近消息、未读数；打开会话即标记已读，约 8 秒轮询新消息。消息限 1～2000 字，按账号每分钟最多 60 条。

商家消息使用 `shop_conversation`、`shop_message` 独立表，与医生的 `consultation_request`、`consultation_message` 完全分开；没有报告 ID、报告正文或医生授权字段。商家账号访问医生消息接口返回 403，医生账号访问商家或用户商城消息接口返回 403。用户只见自己的订单会话，商家只见本店会话；猜测别人的会话 ID 读写均返回 404。这里是教学演示的异步订单聊天，不是在线医疗咨询、药师咨询或即时客服承诺。不要在商家消息中发送病历、报告、处方等敏感资料。

## 手工验收

确保本机后端 8080 已运行 V11 迁移、前端 3000 可访问。

1. 商家甲、商家乙分别登录，确认各自店铺有可售商品并开启演示营业。用户甲在甲店提交一单，用户乙在乙店提交一单。
2. 用户甲在“我的订单”点击“联系商家”，进入商家消息页，看到自动创建的订单会话与默认问候；再次从该订单点击“联系商家”，应回到同一会话而非出现第二条。
3. 用户甲发送一条订单问题。商家甲登录“消息”，看到甲用户及订单编号，进入后未读标记消失，并可回复。用户甲返回“商家消息”可看到回复。
4. 商家乙只能看到乙店会话，看不到甲用户的会话；用户乙也看不到甲用户的会话。商家端不出现“报告 #”或体检报告内容，原医生消息页仍只显示医生咨询。
5. 可按下述命令复现后端、浏览器和压测；压测只允许本机地址，会创建随机 `.invalid` 演示账号，结束时取消测试订单并暂停测试店铺。

```powershell
cd D:\codex++\project\见微知著\server
. .\.env.local.ps1
$env:JWZZ_IT_DB_URL=$env:DB_URL
mvn test
cd ..\web
npm run typecheck
npm run test:e2e
cd ..
node scripts/shop_message_load.mjs
```

## 验证记录

- Flyway V11 已在本机 MySQL 8 应用。`mvn test`：23 项通过、0 失败、0 跳过。新增真实数据库集成测试覆盖：同订单并发打开只创建一条会话和一条首消息；两用户、两商家互不可读写；消息外键失败时会话与消息一并回滚；已读游标与 8 路并发发送消息无丢失。
- `npm run typecheck` 通过；`npm run test:e2e`：9 项通过、2 项因未提供本地演示医生密码按原条件跳过、0 失败。新浏览器用例覆盖两店两用户隔离、用户发起／商家回复、未读归零、跨账号接口 404、商家访问医生消息和报告接口 403、医生访问商城消息 403、商家页面不出现报告内容。
- 本机单次压测原始结果见 [JSON 记录](shop-message-performance.json)，脚本见 `scripts/shop_message_load.mjs`。各读取路由预热 10 次，随后每路由 300 次请求、并发 20；同一会话并发 10 发送 30 条消息，全部持久化且无 HTTP 错误。订单和测试店铺在压测后已关闭／暂停。
